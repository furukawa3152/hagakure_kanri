## この会で押さえたいこと（結論）

1. AI活用＝良いプロンプトを書くこと、ではない
2. 仕事は「線（作って終わり）」から「円（回し続ける）」へ移っている
3. 成長は Prompt → Context → Harness → Loop の外側へ広げること（動画の4段階を根拠に明示）

6. 後半デモで、思想が実装に落ちる瞬間を一緒に見る（行けるところまで）

### 1. なぜ今「ループ」なのか（5分）

解説したい点：

- 昔：考える → 作る → 終わり（線）
- 今：考える → AIが作る → 評価 → 改善 → またAI → …（円）
- 「仕事がなくなる」より「仕事の回し方が変わる」

身近な導入例（短く1つ）：

- 料理：作る → 食べる → 感想 → レシピ変更 → また作る

職場寄りの具体例（2個に絞る）：

1. 医療・事務：文書や確認作業をAIに手伝ってもらう → 人が確認 → 指摘を次の依頼に反映
2. 学習・発信（ブログ等）：書く → 公開 → 反応を見る → 次の書き方を変える

スライドに残す言葉：

> 実は全部ループ。AI特有の話ではなく、仕事・学習・生活の共通構造。

---

### 2. 良いループ／悪いループ（5分）

解説したい点：

悪いループ

```text
やる → 終わる
```

良いループ

```text
やる → 結果を見る → 原因を考える → 次を変える → またやる
```

ここで参加者に気づかせたいこと：

- 多くの人が弱いのは「実行」ではなく「評価」と「改善」
- AIに頼んでも、評価がないとガチャになる
- 「当たりの回答を祈る」状態＝評価ループがない状態

座談用の問い：

> 普段AIに頼んだあと、結果をどうチェックしていますか？
> 「なんとなく良さそう」で終わっていませんか？

### 3. 4段階モデル：Prompt → Context → Harness → Loop（12〜15分）

ここが前半本編の骨格。エージェント不要の言葉で説明する。

出典の明示：

- この4段階は、紹介動画で整理されている枠組みを根拠として使う
- 「自分の思いつきの分類」ではなく、動画の骨格をみんなで共有する、と先に言う
- スライドにも「出典：〇〇（動画タイトル／話し手）」を小さく入れておく

| 段階 | 設計するもの | 普段のAIでの問い | 日常例 |
|---|---|---|---|
| Prompt | 指示 | どう頼めば良い回答が出る？ | 「要約して」「初学者向けに」 |
| Context | 情報 | 何を見せれば判断できる？ | 仕様・過去文・ルール・相手情報を貼る |
| Harness | 制約・安全装置 | どうすれば安心して任せられる？ | チェックリスト、禁止事項、出力形式の固定 |
| Loop | 循環 | 次も自分で回るには？ | 結果を記録し、次の依頼に活かす |

#### 3-1. Prompt（おなじみ）

- 悪いわけではない
- 問題は「AI活用＝プロンプト」で思考が止まること

#### 3-2. Context（今回いちばん日常に効く）

- 頼み方より「何を知っている必要があるか」
- 毎回同じ説明を貼っている人は、Contextが毎回消えている
- スライド例：
  - プロンプトだけ：「この文章を直して」
  - Context付き：「対象読者は塾生初学者。口調は丁寧だが堅すぎない。前回指摘は〇〇」

#### 3-3. Harness（「お願い」と「仕組み」の違い）

エージェントなしでも理解できる言い換え：

- Prompt：必ずテストしてください（お願い）
- Harness：テストに合格しないと次へ進めない（仕組み）

日常版 Harness の例：

- 出力形式を固定する（箇条書き3つ、表、Yes/No + 理由）
- 「わからないときはわからないと言う」をルールにする
- 重要判断は必ず人間確認、と決めておく
- 個人情報・秘密情報は貼らない／マスクする

押さえたい一言：

> AIにお願いするのではなく、守らせる条件を先に置く

#### 3-4. Loop（回す）

- 毎回ゼロから頼むのではなく、前回の結果・反省を次に渡す
- 「1回うまくいった」より「次も再現できる」
- 人間が毎回起動し続ける必要はあるか？を考える入口

ただし今回は「完全自動化」や Human on the Loop まで行かない。
日常レベルでは、Human in the Loop の最小形で十分：

```text
依頼 → 出力 → 自分で評価 → 直させる／次の依頼に反映
```

これが今回いちばん大事な練習。

### 3-5. Human in the Loop / Human on the Loop（短く・2〜3分相当）

用語は出してよいが、深追いしすぎない。対比は1枚で見せる。

| | Human in the Loop | Human on the Loop |
|---|---|---|
| 位置 | ループの中で毎回見る・直す | ループの外で監督する |
| 今の自分 | Chatに頼む → 見る → 直させる | 普段はAIが回り、おかしい時だけ介入 |
| 強み | 考え方が身につく／安全 | 人がボトルネックになりにくい |
| 注意 | 人が毎回止まると遅い | 自動化しすぎると危険な判断まで走る |

今回のスタンス：

```text
目指す景色：Human on the Loop
今日の練習：Human in the Loop
```

言い方の例：

> 最終的には、人が毎回確認しなくても回る形を目指したい。
> でも今日は、まずループの中に入って「評価と改善」を自分でやる。
> 監督席に座る練習の前に、選手として回し方を覚える感じ。

### 4. べからず集（5分）

plan.md の「べからず」を、日常AI向けに言い換えて解説する。

| べからず | なぜ？ | 次に考えること |
|---|---|---|
| 神プロンプトを作るべからず | 指示だけ最適化している | Context |
| AIに全部説明するべからず | 毎回人間が情報を運び続けている | Context の再利用 |
| 「守って」とお願いするだけべからず | 守る保証がない | Harness（形式・禁止・確認） |
| AIを自由に動かすべからず | 失敗も速くなる | Harness |
| 毎回「次これ」と言うべからず | 人間がボトルネック | Loop（前回結果の引き継ぎ） |
| 成果物だけ見るべからず | 本当の成果は外にある | Feedback（公開後・現場の反応） |
| 全部AIに任せるべからず | 人間しか持っていない情報がある | まずは In the Loop で残す |

座談用の問い：

> 最近の自分のAIの使い方で、いちばん当てはまる「べからず」はどれ？

### 6. 後半デモ：Cursor で Slack 品質改善ループを作る（25〜35分）

目的：前半の思想を、動く題材で見せる。完成より「なぜプロンプトだけでは足りないか」に気づくこと。
温度感：デモでも「即・全自動の On the Loop」ではなく、人間確認が入る In the Loop 寄りで見せる。On は「将来こう伸ばせる」と示す程度。
進め方：時間内に行けるところまででOK。途中で止めてまとめに入ってよい。

優先順位（前から順に。後ろは余ったら）：

1. Prompt：投稿を貼って判定させる
2. Context：例外ルールを足して判定が変わる様子
3. Harness：取得範囲・人間確認など条件を口頭〜コードで固定
4. Loop：取得→判定→要確認→人間レビュー、までつなげられれば十分
5. （余力）基準更新や通知の話

題材名の言い方：

- NG：「不適切発言監視システム」（処罰・監視社会っぽい）
- OK：「Slack コミュニケーション品質改善ループ」／ Slack Safety Loop

#### デモで見せる流れ（段階を踏む）

| 段階 | その場でやること | 学べること |
|---|---|---|
| Prompt | 投稿を貼って「不適切か判定して」 | 単発でも動く |
| Context | 社内ルール・例外（冗談・引用・専門用語）を渡す | 判断材料が要る |
| Harness | 取得範囲・保存方針・通知条件・人間確認を決める | お願いではなく仕組み |
| Loop | 取得→判定→要確認抽出→人間レビュー→基準更新 | 回し続ける設計 |

見せたいループ図（今回のデモ＝ In the Loop）：

```text
Slack投稿取得
 → AIが分類・スコアリング
 → 要確認だけ抽出
 → 人間が「問題 / 問題でない」を確認   ← 今日はここを大事に残す
 → 判定基準・プロンプト・ルールを更新
 → 次の投稿監視
 ↺
```

将来の景色（On the Loop・口頭で軽く）：

```text
普段は AI が回す
 ↓
おかしそうな時だけ人間が介入
 ↓
方向を直したら、また AI に戻す
```

#### デモ中に口で強調すること

- 最初は Prompt だけで動く
- でも「冗談は？」「内輪ネタは？」「引用は？」「医療用語は？」で崩れる
- 崩れた瞬間に「問題はプロンプトではない」
- AI判定だけで処分しない（今日は人間確認を残す＝ In the Loop）
- 「即・本人へ自動警告」は今日はやらない（先走りすぎ）
- DMは取らない／特定チャンネルのみ、など Harness の例を口頭で入れる
- On the Loop は「人間確認のうち、定型部分を徐々に外していく先」と説明する

#### デモの進め方メモ

- 発表者が Cursor で画面共有しながら実装・試行
- 参加者は見る／聞く／突っ込み歓迎
- 途中で止まってもOK。止まったところ自体が「評価→改善」の実況になる
- 完成しなくても、「どこに人間を残すか」まで話せれば十分
- 残り時間が少なくなったら、優先順位の途中でもまとめへ切り替える

座談用の問い（デモ後・時間が許せば短く）：

> 今の段階で、人間確認を外してよい作業はある？
> 逆に、今は絶対に人間が中にいるべき場所はどこ？
